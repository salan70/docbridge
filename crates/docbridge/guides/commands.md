# Commands

These are the vNext commands. `docbridge --version` (`-V`), valid only as the first argument, prints `docbridge <version>` on one line and exits 0. `docbridge --help` (`-h`) prints the command list; `<command> --help` prints that command's usage for `init`, `deinit`, and `docs`, and the same list for `validate`, `links`, and `unlinked`. Without `--root`, commands requiring project configuration use the current directory only.

| Command    | Purpose and confirmed options                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `validate` | Check configuration, annotations, targets, duplicates, and read failures. Success exits 0; errors exit 1. Supports `--json` and `--root`. Unlinked items alone are not errors.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `links`    | Show direct relationships. With no arguments, show all links; accept one or more files, directories, globs, or a Markdown section ID. An existing directory, `dir` or `dir/`, selects the same managed files as `dir/**` would. The name is taken literally, so a directory such as `src/[slug]` works even though the glob `src/[slug]/**` is rejected. A glob selects managed file paths (`*` within a segment, `**` recursively), unlike configuration paths, which select directories searched recursively. `--sections` instead lists the section IDs of the selected files without traversing link edges. Supports `--stdin`, `--json`, `--include-content`, `--ignore-unmanaged`, and `--root`. |
| `unlinked` | List unlinked code files and Markdown regions. Accepts the same file, directory, glob, and `file#section` selectors as `links`, plus `--stdin` and `--ignore-unmanaged`, to scope the report: a file or directory selection includes that file's preamble, and a section selection reports only that subtree. Supports `--json` and `--root`. Unlinked items alone are not failure. Incomplete analysis must not appear as a complete result.                                                                                                                                                                                                                                                          |
| `init`     | Suggest configuration and install a Skill. Supports `--dry-run`, `--yes`, `--root`, `--claude`, and the restricted `--force` described in [Configuration](configuration.md).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `deinit`   | Safely remove project assets, with `--dry-run` and confirmation before execution. See [Removal](deinit.md).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `docs`     | Show a short start and guide list; `docs list` lists guides and `docs show <name>` shows one. An unknown name exits 3.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `help`     | Print the command list; `help <command>` equals `<command> --help`, and `help` alone equals `--help`. An unknown command name or extra operands exit 3.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

`links` follows direct edges only. A nonexistent plain file, nonexistent section, invalid selector or unreadable file is an error; an empty valid glob or directory succeeds. A section ID is the full heading path (`document.md#parent/child`); a section selector that matches no section lists candidate section IDs from the same file that can be pasted back. Text output lists selected nodes first, then non-code nodes, then code nodes; each selected code file shows its incoming section links as an indented `<- <section>` line, or `(no incoming links)` when none exists. If usable results remain despite errors, exit 2; if none remain, exit 1. Warnings and errors go to stderr. Query JSON includes nodes, edges, diagnostics and `complete`, with deterministic root-relative IDs and ordering. Stdin accepts one selector per line, ignoring blanks and deduplicating before determining the effective target count. Content is complete and untruncated: code includes the whole file and Markdown includes the heading and descendants through the next same-or-higher heading. Overlapping source ranges are merged into blocks, while every selected or referenced section remains a node with its own line range. LF and CRLF are line breaks; content output preserves stored bytes.

With `--ignore-unmanaged`, a selector naming a path outside the configured managed set — a file, a directory, or a section such as `tool/x.py#build` — is skipped without a `selector` diagnostic, so a changed-file list can feed `links` or `unlinked` directly: `git -c core.quotePath=false diff --name-only --diff-filter=d origin/main...HEAD | docbridge links --stdin --ignore-unmanaged`. Missing sections on managed files still list candidate IDs; invalid section selectors, missing or unreadable managed files, and unsafe paths are still reported. When every input is unmanaged and the project has no other diagnostics, the result is an empty, complete graph and exits 0. Project-wide diagnostics, such as a broken annotation elsewhere, are still reported and make the result incomplete. Without the flag, selection is unchanged.

`unlinked` treats a linked parent as covering all descendants. When only a child is linked, the uncovered parent region excludes that child and the annotation lines attached to it. Fully unlinked descendants are grouped under their topmost unlinked region; meaningful pre-heading or headingless content is a separate region. With no selectors the report covers the whole project; selectors scope it. A section selector reports only that subtree, and a preamble appears only when its whole file was selected. Selector errors are diagnostics that exit 1. Invalid links do not count as coverage or make an incomplete scan complete. The CLI checks structure, not semantic agreement. See [Automation](automation.md).

Success exits 0, validation, configuration, I/O and incomplete scans exit 1, partial `links` exits 2, and invalid arguments exit 3 for every command. Safety: `init` and `deinit` make no writes without confirmation, either an interactive prompt or `--yes`; `--dry-run` never writes. Each file changes atomically; if a run fails partway, it lists the files that changed and those that did not, and running the same command again finishes the rest.

The CLI does not update itself; update it through its installation method. Release targets are static Linux x64 and ARM64 musl, macOS x64 and ARM64, and Windows x64. Publication is pending.
