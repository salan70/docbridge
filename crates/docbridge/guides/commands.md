# Commands

These are the seven vNext commands. Without `--root`, commands requiring project configuration use the current directory only.

| Command    | Purpose and confirmed options                                                                                                                                                                                                                                                                                                                    |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `validate` | Check configuration, annotations, targets, duplicates, and read failures. Success exits 0; errors exit 1. JSON contains diagnostics and a summary. Unlinked items alone are not errors.                                                                                                                                                          |
| `links`    | Show direct relationships. With no arguments, show all links; accept one or more files, globs, or a Markdown section ID. A glob selects managed file paths (`*` within a segment, `**` recursively), unlike configuration paths, which select directories searched recursively. Supports `--stdin`, `--json`, `--include-content`, and `--root`. |
| `unlinked` | List unlinked code files and Markdown regions; supports `--json`. Unlinked items alone are not failure. Incomplete analysis must not appear as a complete result.                                                                                                                                                                                |
| `init`     | Suggest configuration and install a Skill. Supports `--dry-run`, `--yes`, `--root`, `--claude`, and the restricted `--force` described in [Configuration](configuration.md).                                                                                                                                                                     |
| `deinit`   | Safely remove project assets, with `--dry-run` and confirmation before execution. See [Removal](deinit.md).                                                                                                                                                                                                                                      |
| `docs`     | Show a short start and guide list; `docs list` lists guides and `docs show <name>` shows one. An unknown name exits 3.                                                                                                                                                                                                                           |
| `upgrade`  | Update the standalone binary after SHA-256 and Ed25519 signature verification. Supports `--check`, `--dry-run`, and `--yes`; package-managed and Nix installations receive update guidance instead.                                                                                                                                              |

`links` follows direct edges only. A nonexistent plain file, nonexistent section, invalid selector or unreadable file is an error; an empty valid glob succeeds. If usable results remain despite errors, exit 2; if none remain, exit 1. Warnings and errors go to stderr. Query JSON includes nodes, edges, diagnostics and `complete`, with deterministic root-relative IDs and ordering. Stdin accepts one selector per line, ignoring blanks and deduplicating before determining the effective target count. Content is complete and untruncated: code includes the whole file and Markdown includes the heading and descendants through the next same-or-higher heading. Overlapping source ranges are merged into blocks, while every selected or referenced section remains a node with its own line range. Text labels a child already included in its parent and separates Links and Contents. LF and CRLF are line breaks; content output preserves stored bytes.

`unlinked` treats a linked parent as covering all descendants. When only a child is linked, the uncovered parent region excludes that child and the annotation lines attached to it. Fully unlinked descendants are grouped under their topmost unlinked region; meaningful pre-heading or headingless content is a separate region. Invalid links do not count as coverage or make an incomplete scan complete. The CLI checks structure, not semantic agreement. See [Automation](automation.md).

Success exits 0, validation, configuration, I/O and incomplete scans exit 1, partial `links` exits 2, and invalid arguments exit 3 except `validate` argument errors, which exit 1. A newer version found by `upgrade --check` is not a failure. `--check` and `--dry-run` never replace the binary; noninteractive upgrade without `--yes` cannot replace it.

Upgrade selects the latest stable GitHub release. Self-replacement requires a standalone installation receipt bound to the executable path and installed hash; known managed locations take precedence, and direct downloads without a receipt receive guidance. Before replacement, verify the signed manifest with its trusted Ed25519 key and check schema, release version, target, filename and SHA-256. Reject replay, downgrade and tag or target mismatches. Download and verify beside the executable, retain a recoverable backup and use platform-appropriate atomic replacement. Windows renames the running binary aside before moving the verified replacement into place and defers safe cleanup. Report recovery paths if restoration fails. Production keys and publication are pending. Planned targets are static Linux x64 and ARM64 musl, macOS x64 and ARM64, and Windows x64; consult actual release requirements rather than assuming minimum OS versions.
